# 0014 文档版的批量管理与原文下方编辑

日期：2026-10-28｜状态：已采纳｜范围：圈批·文档（diple-docs）

## 背景

V3-D（ADR 0012）做了清单收起，但入口只是清单头部右上角一个小图标，用户找不到，又提了一次「要有收起功能」。用户还要「一键清除等功能」，以及此前提过的「批注栏的输入框要在文字下方」。

## 决定

1. **收起开关放到页面工具栏**（`rail.jsx` 的 `PanelSwitch`），在「排版 / 源码」、刷新、文件夹那一排的最后，用常见的「切换侧栏」图标（`codicon-layout-sidebar-right`，收起后是 `-off`；RTL 镜像）。悬停提示是「收起标注清单 / 展开标注清单」，不带键帽；收起时按钮上显示未处理数，展开时不显示。
   - 清单头部原来的开关删掉，同一件事只留一个按钮。页边状态条的「展开」保留（收起后清单所在的位置本身就是入口），顶部只留展开和上一条/下一条，未处理数只在工具栏显示一次（V3-D2-I）。
   - 补充（R11-I，2026-10-29，用户要求）：细条不再有自己的「展开」按钮（原来细条顶部那个对话框图标）。收起时工具栏的「切换侧栏」就在细条正上方，两个按钮做同一件事，与上面「同一件事只留一个按钮」相悖；用户也指出了重复。现在细条顶部只有上一条 / 下一条，收起状态下整页只有工具栏这一个开关，收起、展开后焦点都留在它上面（`preventScroll`）。底栏布局不受影响，底栏开关仍是那里唯一的开关。
   - 页面低于 560px（底栏布局；V3-D2-I，含 560px 时仍在右侧）不显示工具栏开关：底栏那一条本身就是开关。
2. **「⋯」批量菜单**（`list.jsx` 的 `MoreMenu`，复用 desktop-kit 的 `SendMenu` 外壳，只用它的键盘、焦点和关闭行为）：清除全部 / 已解决 / 已发送·已回应 / 原文已变（各带数量，0 条的灰掉），有筛选时多一项「清除当前筛选的 N 条」；全部标为已解决；复制全部为 Markdown。哪一项拿哪些条目由纯函数 `review/bulk.js` 的 `bulkPlan` 决定，格式由 `copyAll` 决定（core `CopyText.block`，和单条复制同一个格式）。
3. **清除不弹确认，给约 8 秒撤销**（`UNDO_MS`），手感和聊天版「全部清空」一致。后端新增三个端点，各自一个事务、要么全做要么全不做：
   - `POST /items/bulk-delete {path, ids, expectMutations}` → 返回被删条目的快照；
   - `POST /items/bulk-restore {items}` → 原样放回（同一个 id，`INSERT OR IGNORE`，点两次撤销无害）；
   - `POST /items/bulk-resolve {path, ids, expectMutations}`。
   - 任何一条已不存在、属于别的文件、或在别处改过（`mutation` 不符），整个调用返回 409 `stale`，什么都不做；页面重读清单，提示用户。
   - 清除只删清单里的条目；已发出的交接记录和聊天里的内容不受影响。
4. **意见在原文下方写**（`float-editor.jsx` + 纯函数 `float.js` 的 `placeFloat`，规则照聊天版 V3-T 重写一份，本轮不把聊天版代码搬进 desktop-kit）：
   - 选中文字点「标注」、或点卡片的「编辑意见」（双击意见、卡片上按 Enter 同样），浮层出现在原文正下方：上面是原文，中间是意见框，底部照聊天版 V2.1：起始侧一个「重新选取原文」图标，末尾侧「保存并发送」和主按钮「保存」，都不带键帽。下方放不下就翻到上方。
   - 浮层是 `.er-docwrap` 里的绝对定位元素，坐标在滚动空间里，所以随原文滚动，滚动时不测量；不放进 `.er-doc`，文档区仍然只读。
   - 意见框就是卡片原来的 `CommentEditor`：保存、冲突提示、输入法、文件刷新暂缓（hold）的规则一条不变。
   - 清单展开、收起都这样；收起时不再临时展开清单，ADR 0012 第 3 条的 `peek` 删除。
   - 「编辑意见」先平滑滚到原文（不闪），按滚动后的位置放浮层。
   - 例外：原文已变（找不到原文）的条目没有地方挂浮层，仍在卡片里编辑；卡片里的编辑器只留给这种情况。
   - 保存后浮层关闭，这一条设为当前条，清单展开时卡片滚进视野。
5. **清单头部三行**：标题和条数、上一条/下一条、「⋯」；筛选单行，放不下横向滚动；「发送 N 条 ▾」和目标会话名（省略号，悬停显示全名）。

## 后果

- `shared/api.js`（P 路归属）在对象末尾多了三个方法 `bulkDelete / bulkRestore / bulkResolve`，合并时注意和 P 路的改动放在一起。
- 「保存并发送」和发送菜单的「发到当前会话」是同一个动作（明确点击才发，不自动发送）。没有当前会话或对端不可用时灰掉。
- 新增私有测试 `tests/desktop/v3d2-list.test.mjs`、`tests/python/test_review_bulk.py` 和本 ADR 已加入 `scripts/export-public.mjs` 的排除清单。

## 集成收尾（V3-D2-I）

- 页面常停靠在聊天右侧，1440px 窗口里页面约 590px；左右布局门槛下调至 560px（文档 300 + 清单 260）。先压窄清单，低于门槛才切到底栏，不改变记住的宽度。
- 文档版 9 种语言的意见框占位文字只说明要写什么，不含按键提示；聊天版编辑框已无提示。`v21-no-keycaps` 同时守卫本地化和代码里的占位文字。

## 补充（R11-K：菜单的关闭原因和焦点）

- 「⋯」和发送菜单（desktop-kit `SendMenu`，两个插件共用）关闭时会带上原因：`escape` / `tab` / `select` / `outside` / `scroll`。
- 菜单开着时，Esc 在 document 的捕获阶段统一处理，并且不再往下传。这样，焦点不在菜单里时（比如点了一下灰掉的条目），Esc 也能关掉菜单；同时开着的草稿浮层收不到这次 Esc，草稿不会被丢掉。
- 只有按 Esc、选中一项或按 Tab 关闭时，焦点才回到触发按钮（按 WAI-ARIA 菜单按钮的惯例），并且不滚动页面。点菜单外面或滚动关闭时不动焦点：在文档里按下鼠标拖选，选区会完整保留。之前不管怎么关都会把焦点拉回按钮，拖选因此被打断，只剩一个字。

- R11-L（XR11e-03/04/05）：
  - 打开的菜单记在窗口上一个共用的栈里（`window[Symbol.for('diple.desktop-kit.menus')]`）。两个插件各打一份 desktop-kit，但用的是同一个栈，document 上也只有一个 Esc 监听：谁先打开菜单谁注册，最后一个菜单关掉时移除。一次 Esc 只关最上面的那个菜单，然后 `stopImmediatePropagation`。
  - 输入法组字时按的 Esc（`isComposing` 或 `keyCode === 229`）归输入法，菜单不处理，也不 `preventDefault`。
  - 焦点在宿主的弹窗里（`[aria-modal="true"]` 或 `[role="dialog"]`），而这个弹窗不包含当前菜单时，这次 Esc 归宿主，菜单不动。
  - 边界：菜单的监听在打开第一个菜单时才注册。宿主如果更早在 document 上注册了捕获阶段的 keydown 监听，它会先于菜单拿到 Esc。插件无法改变这个顺序，也不做保证。`send-menu-esc.test.mjs` 记录了现在的顺序：宿主先拿到，然后菜单关闭。

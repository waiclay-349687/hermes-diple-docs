# 0013 文档版的打开位置随 Hermes 预览，聊天卡片的计数合并成一次请求

日期：2026-10-28｜状态：已采纳｜范围：圈批·文档（diple-docs）

## 背景

1. 审阅页调用 `host.openWorkspace(id, …)` 时没传 `dock`，宿主默认 `{ pane: 'workspace', pos: 'center' }`，审阅页作为标签叠进聊天所在的区，把聊天盖住。Hermes 自己的文件预览不是这样：第一个预览停靠在主区右侧，之后的预览作为标签叠进这个区（宿主 `app/chat/preview-tile.tsx` 的 `existingPreviewAnchor`、`watchPreviewTileMirror`，最小宽度 22rem）。用户要求「打开默认和 Hermes desktop 的打开预览的位置设计相同」。
2. 用户的 `desktop.log` 里，2026-10-27 11:11:14 和 10-28 14:50 两次启动，同一毫秒内各发出几十个 `GET /api/plugins/diple-docs/items?path=…`（10-27 那次 121 条），全部报 `Gateway ticket bootstrap failed`。来源是聊天记录里每张 `::diple-docs{path}` 卡片各自取一次条数；gateway 还没就绪，失败后卡片不再重试，只能等 20 秒一次的轮询。

## 决定

1. **一条打开规则**（`review/placement.js` 的 `dockFor`），按顺序：
   - 已有我们的标签（文档页或「最近的文档」）在布局里 → `{ pane: 那个标签, pos: 'center' }`，叠进它所在的区；
   - 否则已有 Hermes 预览（`preview-tile:*`）→ 叠进预览区；
   - 否则 `{ pane: 'workspace', pos: 'right' }`，停在主区右侧，聊天仍然可见。
   - 最小宽度一律 `22rem`（原来 26rem），和预览一致。
   - 打开文档、恢复标签页（`restoreTabs`）、最近的文档（⌘K 行和「最近的文档」页）、聊天卡片，全部经过 `openTile`，没有第二条路。
2. **怎么知道布局里有什么**：SDK 没有查询布局的接口（`paneVisibility` 只能问已知 id，查不到 `preview-tile:*` 的 id）。所以集中在 `readLayoutPanes` 一个函数里读宿主 DOM：每个停靠的 pane 都有一个标签 `[data-tree-tab=<paneId>]`（宿主 `components/pane-shell/tree/renderer/tree-group.tsx`）；预览和插件标签都是 `placement: 'main'`，单独一个也会显示标签（`strip-visibility.ts` 的 `stranded`）。一个标签都读不到时返回 null，退回到「叠进自己的区，否则停在右侧」。
3. **锚点必须已在布局里**：宿主收养 pane 时，如果锚点不在树里，`center` 会落到主区（`store.ts` 的 adoption），等于又盖住聊天。所以布局里找不到的旧标签不当锚点；例外是 2 秒内刚打开、还没被收养的标签（重新加载时一次恢复好几个），这和宿主「同一批到达的以第一个为头」一致。锚点总是更早打开的标签，不会成环。
4. **卡片计数合并请求**（`review/item-counts.js`）：卡片不再自己请求，而是 `rt.itemCounts.watch(path, fn)`。
   - 16ms 内要的路径合并成一次 `POST /items/summary { paths }`，后端一次 SQL 按路径和状态分组，返回 `{ counts: { [path]: { total, open, byStatus, lost, itemsVersion } } }`。只读，一次最多 200 个路径；坏路径在自己那一项里写 `error`，不影响别的。返回的键就是请求时的原样路径，卡片按自己的字符串取。
   - 失败按 1、2、4、8、15、30 秒退避重试，之后每 30 秒一次，一直重试，直到成功；重试期间卡片只是不显示条数，不显示错误，也不转圈。成功后退避清零。
   - 刷新：一个 20 秒的定时器，一次请求刷新所有在屏卡片；窗口隐藏时跳过；没有卡片时停掉。交接结果出来（`onItemsChanged` / `onSettled`）时 `invalidate()`，也只发一次。
   - 兼容：前端热加载、Python 后端还是旧版时，`/items/summary` 返回 404/405，自动退回逐个 `GET /items`，一次只发一个，不会再成风暴。

## 后果

- 新增私有测试 `tests/desktop/v3d2-placement.test.mjs`、`tests/desktop/v3d2-item-counts.test.mjs`、`tests/python/test_review_summary_v3d2.py`。
- `readLayoutPanes` 依赖宿主的 `data-tree-tab` 属性。宿主改了这个属性名时，退回到「叠进自己的区，否则停在右侧」，不会盖住聊天，但不会再叠进预览区。真机 e2e `tests/e2e/v3d2-place.mjs` 会发现这种变化。
- 用户把审阅标签拖进聊天所在的区以后，新打开的文档也会叠进那里：跟着用户的摆法走。
- 没改 `packages/core`、`packages/desktop-kit`。
